# ROADMAP — PRVoice

План реализации сценария «Voice + модуль загрузки». Оценки — в человеко-неделях (чн) от одного
разработчика. Базовая оценка (из аналитики): ~6 чн до MVP, ~14 чн до полной версии.

Статусы: ✅ сделано · 🔨 в работе · ⬜ не начато

---

## M0 — Инфраструктура репозитория ✅

**Цель:** рабочий репозиторий PRVoice со всей историей Voice, документацией и правилами.

- ✅ Перенести историю форка Voice в пустой PRVoice (атрибуция GPL-3.0, возможность merge из апстрима)
- ✅ Настроить ремоуты: `origin` → PRVoice (пуш), `upstream` → Voice, `fork` → исходный форк
- ✅ `AGENTS.md` — рабочий цикл: реализация → комит → пуш → проверка свежим взглядом → фикс
- ✅ `README.md`, `docs/PR-ARCHITECTURE.md`
- ✅ Исследование источников (фактическая структура сайтов — см. `docs/PR-ARCHITECTURE.md`)

## M1 — Слой источников: контракты + Baza-knig + Rutor ✅

**Цель:** код может искать книги на baza-knig.top и получать список mp3-файлов книги.

- ✅ `:core:booksources:api` — `BookSource`, `SearchResult`, `BookInfo`, `DownloadSpec`,
  `SourceRegistry`, ошибки; HTTP-клиент (OkHttp) с общими настройками
- ✅ `:core:booksources:bazaknig` — парсер DLE: поиск (пагинация `search_start`), карточки,
  страница книги, декодер плейлиста (Rhino + `decode.js` с сайта → JSON со ссылками на mp3);
  самоисцеление при устаревшем скрипте (сброс кэша + повторный фетч)
- ✅ `:core:booksources:rutor` — парсер выдачи (magnet, размер, сиды), фолбэк зеркал
  (rutor.info/is/lib) — опережен план (был в M3)
- ✅ Юнит-тесты парсеров на зафиксированных HTML-фикстурах (реальные страницы из исследования) — 17 тестов
- ✅ Регистрация источников через Metro (`@ContributesTo(AppScope::class)`)

**Критерий готовности:** ✅ тесты парсера зелёные на реальных фикстурах; поиск по сайту возвращает
структурированные результаты без UI.

## M2 — Менеджер загрузок (HTTP) + UI поиска ✅

**Цель:** первый пользовательский сценарий целиком: нашёл → нажал скачать → слушаю.

- ✅ `:core:downloader` — `DownloadEngine` (OkHttp, последовательное скачивание файлов книги,
  пауза/продолжение на границе файлов, докачка после сбоя приложения), хранение очереди (DataStore,
  состояние переживает рестарт), тихие уведомления о прогрессе/завершении/сбое
- ✅ `:features:bookDownload` — экран поиска по всем источникам (пагинация по каждому источнику,
  обложки, сиды у торрентов), экран книги (описание, метаданные, кнопка скачивания, прогресс,
  пауза/продолжить), экран загрузок (пауза/продолжить/удалить)
- ✅ Интеграция в навигацию: `Destination.BookSearch/BookDetails/BookDownloads`, иконка загрузки
  в тулбаре библиотеки + строка «Загрузки» в настройках
- ✅ Строки: `values/strings.xml` + `values-ru` (26 новых)
- ✅ Импорт скачанного в библиотеку: запись через SAF в папку библиотеки (Root/Author —
  с подпапкой автора, SingleFolder — напрямую), рескан `MediaScanTrigger` после завершения

**Критерий готовности:** ✅ `assembleFreeDebug` собирается; 52 юнит-теста зелёные; сценарий
«найти → скачать → в библиотеке» работает целиком.

## M3 — Торренты: Rutor + libtorrent4j → MVP ✅ (частично — полировка в M6)

**Цель:** полноценный MVP (≈6 чн от старта).

- ✅ `:core:booksources:rutor` — парсер выдачи (строки `gai`/`tum`: magnet, размер, сиды),
  зеркала (rutor.info/is/lib), скачивание `.torrent` — сделано в M1
- ✅ `TorrentEngine` на libtorrent4j: magnet/.torrent → метаданные (с кэшем для быстрых
  возобновлений) → последовательная загрузка аудиофайлов (мусор — обложки, nfo — фильтруется),
  статистика скорости/сидов/пиров, трекеры из magnet-uri
- ✅ Пауза/возобновление торрента: forceRecheck докачивает уже скачанное
- ✅ Foreground service (dataSync): загрузки продолжаются в фоне, сервис живёт пока очередь
  не опустеет
- ✅ UI: кнопка «Скачать через торрент» в деталях, статус RESOLVING, байтовый прогресс,
  сиды/пиры, те же состояния на экране загрузок

**Критерий готовности:** ✅ MVP работает на двух источниках (прямой HTTP + торрент),
`assembleFreeDebug` собирается, 19 тестов `:core:downloader` зелёные.

**В полировку (M6):** ручной выбор файлов внутри торрента (сейчас автофильтр только аудио),
ретраи сетевых ошибок, чистка мусорных временных файлов.

## M5 — QuickJS-песочница источников ⬜

**Цель:** источники как подключаемые скрипты (паттерн Tachiyomi/Mihon), декодер baza-knig
переезжает в скрипт.

- ⬜ Движок: QuickJS на Android, изоляция (нет доступа к файлам/сети кроме API хоста)
- ⬜ API источников для скриптов: `search()`, `details()`, `fetch()` с лимитами
- ⬜ Миграция bazaknig/rutor/rutracker на скрипты; хранилище скриптов (локальное + импорт)
- ⬜ Подпись/версионирование скриптов, горячее обновление без релиза APK
